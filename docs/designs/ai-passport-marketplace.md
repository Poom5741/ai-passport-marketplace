## Problem Statement

AI Passport is Thailand's government AI learning platform. Learners who complete courses have nowhere dedicated to showcase the products and web apps they build. They currently don't share publicly — projects live on GitHub (unseen) or get posted to Facebook groups (ephemeral, not a portfolio). There's no place that says "I built this as an AI Passport learner."

---

## What Makes This Cool

A Product Hunt for AI Passport graduates — a community hub where builders post their projects, get discovered, and connect with each other. Each builder has a public profile that functions as a portfolio tied to their AI Passport credential. The hub itself becomes worth visiting even before you've posted: discover what others are building, see what's trending, find collaborators.

---

## Constraints

- No existing codebase — starting from scratch
- Learning/side project context — no deadline pressure, but want to build something real
- Need to work within Thailand's government AI education ecosystem

---

## Premises

1. **AI Passport learners want a dedicated place to showcase their builds** — not already well-served by GitHub or social media.
2. **Engagement stats (views) motivate builders** — they care about who looked at their work.
3. **The credential badge from AI Passport** is valuable but not MVP-critical — can be added later.
4. **Learners currently don't share publicly** — strong green field, no existing dedicated hub.

## Approaches Considered

### Approach A: Minimal Viable
- Next.js + Supabase (auth, profiles, project feed, submission form, view counts)
- One public feed + individual profile pages
- Ship in days, not weeks
- **Ruled out:** Chose Full Platform instead for proper architecture

### Approach B: Full Platform
- Next.js + Cloudflare Workers, D1 (database), R2 (screenshot storage)
- Full auth, profiles, project feed, submission, tag-based discovery, view counts
- Scalable from day one
- **Chosen**

### Approach C: Community-First
- Same core but with daily featured projects, "most viewed this week" leaderboard, tag-based discovery
- Hub you visit even without posting
- **Ruled out:** Build this after core is stable

## Recommended Approach

**Full Platform on Cloudflare**

- **Frontend:** Next.js (App Router) deployed to Cloudflare Pages
- **Auth:** Cloudflare Workers with JWT sessions (stateless, stored in HttpOnly cookie). JWT signed with HS256, secret via `wrangler secret put JWT_SECRET`. Token expires in 7 days. No refresh token — user re-authenticates.
- **Database:** Cloudflare D1 (SQLite at the edge)
- **Storage:** Cloudflare R2 + Cloudflare Images for project screenshots. Screenshot upload via Worker proxy (Worker receives upload, streams to R2). Cloudflare Images handles resize to 400px thumbnail + 1200px full. screenshot_url points to Cloudflare Images URL.
- **Features:**
  - User registration + builder profiles
  - Project submission form (title, description, screenshot upload to R2, tags, live URL, repo URL)
  - Public project feed with filtering by tag, sort by newest/most viewed
  - Individual project pages
  - Profile pages showing all projects + view counts
  - View counts on projects and profiles (server-incremented; dedup: same IP+UA hash within 1 hour = no new increment)
  - (Future: comments, reactions, full-text search, credential badge verification)

**Screenshot constraints:** PNG/JPG/WebP, max 5MB. Worker receives upload, streams to R2. Cloudflare Images resizes on delivery. Upload fails gracefully with user-facing error message.

**Tag constraints:** Stored in `project_tags` table (separate from projects). Tags normalized to lowercase, trimmed, deduped on save. Max 10 tags per project.

**Password hashing:** bcrypt with cost factor 10.

## Success Criteria

- A builder can register, post a project, and share their public profile link
- Visitors can browse projects, click through to live demos/repos
- Profiles show view counts
- Something worth showing to another human exists

**Estimated timeline:** 2-4 weeks for one builder (estimate — Cloudflare edge runtime has quirks that may extend this)

## Distribution Plan

This is a web service. Deployment: Cloudflare Pages + Workers. CI/CD via GitHub Actions pushing to Cloudflare on merge.

## Next Steps

1. **Set up Cloudflare project** — create Next.js app, link to Cloudflare Pages, configure D1 database, set up R2 bucket, enable Cloudflare Images
2. **Auth system** — registration, login, JWT via Cloudflare Workers (HttpOnly cookie, 7-day expiry, bcrypt password hashing with cost 10)
3. **Database schema (D1):**
   - `users`: id (UUID), email, password_hash, name, avatar_url, created_at
   - `projects`: id (UUID), user_id (FK), title, description, screenshot_url, live_url, repo_url, view_count (integer), created_at
   - `project_tags`: project_id (FK), tag (TEXT) — PRIMARY KEY (project_id, tag), INDEX on tag
   - `project_views`: id, project_id (FK), viewer_ip, viewer_ua_hash, viewed_at (for deduplication)
   - `profile_views`: id, profile_user_id (FK), viewer_ip, viewer_ua_hash, viewed_at
4. **Avatar upload** — user can upload avatar on profile edit page (same R2 signed URL + Cloudflare Images flow). Falls back to initials-based avatar if not set.
5. **Builder profile page** — public URL per user showing their projects + avatar/name + profile view count
6. **Project submission form** — title (max 100 chars), description (max 2000 chars), screenshot (required, 5MB max PNG/JPG/WebP), tags (optional, max 10), live URL (required), repo URL (optional)
7. **Public project feed** — newest first, filter by tag, sort by newest/most viewed, pagination
8. **Individual project pages** — full description, screenshot, links, view counts
9. **Screenshot upload** — Worker receives upload, streams to R2. Cloudflare Images resizes to 400px thumbnail + 1200px full. Returns Cloudflare Images URL.
